## Nix Build Dependencies

**Auto-generated NuGet report does not include Nix system dependencies.**  
These must be verified manually using Nix commands:

```bash
# List all runtime dependencies with sizes
nix path-info -rsSh .#docker

# Show full dependency tree
nix-store --query --tree $(nix build .#docker --print-out-paths --no-link)

# Check license for specific package
nix eval nixpkgs#dotnet-sdk_8.meta.license
# Output: { fullName = "MIT License"; ... }

# Verify all dependency licenses
nix-store --query --requisites $(nix build .#docker --print-out-paths --no-link) | \
  xargs -I{} nix-store --query --binding license {}
```

**Typical Nix Dependencies:**
- dotnet-sdk_8: MIT (runtime)
- bash, coreutils: GPL (build-time only, not distributed)
- glibc: LGPL, openssl: Apache-2.0 (runtime base layers)

**Note:** GPL build tools are acceptable as they're not part of the distributed artifact.

## Maintenance Procedures

### When Adding New Dependencies

1. **Before adding:** Check license on NuGet.org or project repository
2. **Verify compatibility:** License must be on approved list
3. **Update report:** Run `dotnet run --project tests/SysDocs.Tests -- --license-compliance`
4. **Run compliance test:** Ensure `Constraint_ShouldUseOnlyOpenSourceDependencies` passes
5. **Commit both:** Include dependency and updated `LICENSE_COMPLIANCE.md`

### Quarterly Audit Schedule

**Q1 (March):** Full license audit
- Regenerate compliance report
- Review all Nix dependencies
- Check for license changes in updated packages

**Q2 (June):** Minor audit
- Regenerate report after dependency updates
- Verify no new warnings

**Q3 (September):** Full license audit
- Regenerate compliance report
- Review Nix dependency changes
- Update approved license list if needed

**Q4 (December):** Minor audit
- Year-end compliance verification
- Update this summary document
