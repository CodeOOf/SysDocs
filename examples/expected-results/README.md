# Expected Results Directory

This directory contains **actual PDF files** generated by SysDocs that serve as the baseline for byte-for-byte verification.

## Purpose

When running automated tests, SysDocs generates PDF outputs that are **byte-for-byte compared** (via SHA256 hash) against these expected result PDFs to verify:

1. **Determinism (FR-06, NFR-01)**: Same input produces identical output (exact binary match)
2. **Cross-Platform (FR-14)**: Linux, Windows (Docker), macOS (Docker) produce identical output
3. **Regression**: Changes to SysDocs don't unintentionally alter output

## Test Verification Method

Tests perform **byte-for-byte comparison** using SHA256 hashes:

```bash
# Generate test output
sysdocs --input examples/adns-project/12_SRS_ADNS.md --output test_output.pdf

# Compute hashes
sha256sum test_output.pdf examples/expected-results/individual/01_markdown.pdf

# Expected: Both hashes are IDENTICAL
```

### What Gets Verified

1. **Exact Binary Match**: Generated PDF must be byte-for-byte identical to expected PDF
2. **Hash Comparison**: SHA256(generated) == SHA256(expected)
3. **No Variation**: Any change in output (even metadata) will fail the test

This ensures:
- **FR-06**: Deterministic output (same input → same output)
- **NFR-01**: Reproducible builds
- **FR-14**: Cross-platform consistency hashes = [sha256(output) for output in outputs.values()]
    assert len(set(hashes)) == 1  # All hashes identical
```

## Test Workflow

### 1. Development Phase
- Make changes to SysDocs
- Run tests against existing expected results
- If test fails, investigate:
  - Is it a bug? → Fix code
  - Is it an improvement? → Regenerate expected results

### 2. Expected Results Update
When intentionally changing output format:

```bash
# Regenerate all expected results
make regenerate-expected-results

# Or manually:
./scripts/regenerate-expected-results.sh
```

### 3. CI/CD Pipeline
```yaml
- name: Run Format Tests
  run: |
    pytest tests/test_formats.py -v
    
- name: Verify Determinism
  run: |
    pytest tests/test_determinism.py -v
    
- name: Cross-Platform Test
  run: |
    pytest tests/test_cross_platform.py -v
```

## Notes

- **Expected results are not committed to git by default** (too large)
- CI/CD generates expected results on first run, then caches them
- Developers can generate locally: `make generate-expected-results`
- When updating expected results, document the reason in commit message
- Use `git lfs` if committing large PDF files to repository
## Version Control

### Option A: Commit PDFs with Git LFS
```bash
# Track PDF files with Git LFS
git lfs track "examples/expected-results/**/*.pdf"
git add .gitattributes
git add examples/expected-results/
git commit -m "Add expected results PDFs for test verification"
```

### Option B: Generate in CI/CD
- Don't commit PDFs to git
- CI/CD generates expected results on first run
- Cache them for subsequent test runs
- Faster for developers (no large files to clone)

### When to Update Expected Results

Update and regenerate expected PDFs when:
1. **Intentional output format changes** (new features, improvements)
2. **Bug fixes** that change output
3. **Dependency updates** that affect rendering

**Always document the reason** in the commit message:
```bash
git commit -m "Update expected results: Fix table rendering in LaTeX import"
```
